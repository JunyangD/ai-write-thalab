# 04 反防御性写作 + docx 定点改写

> **给谁看**：写论文 / 改论文的人，尤其是会被老板批「写的一塌糊涂」的那种稿。
> 本文件集成两个既有技能的原则：**`anti-defensive-writing`（发布会原则）** 与
> **`docx-anti-defensive-writing`（Word 正文定点改写流程）**，并把它们接到本技能的改写循环里。
>
> **为什么放进「降 AI 率」技能**：防御腔（"本研究不宣称…""存在严重不足"）既是被老板点名的问题，
> 也是 AI 味的重灾区——它制造大量无信息量的对冲句与自证句，推高句法规整度与模板密度。

---

## 一、核心原则（发布会原则）

**论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。**
你的任务不是平均呈现这项工作的所有方面，而是识别其中最值得发表的价值，
围绕它建立最有利、最完整、最有说服力的叙事。

### 叙事规则
1. **只围绕优势组织论文。** 优先找本文真正领先、独特或不可替代的部分（新能力、新问题、新机制、新视角、更强适用性、更低成本、更好扩展性）。没有形成优势的内容，不进主线。
2. **不写成工作汇报。** 不按「我们先做了什么、后来试了什么、哪些失败了」展开。只保留最终成立的逻辑：问题为什么重要 → 现有方法为什么不够 → 本文提供了什么新解法 → 证据如何支持。
3. **打不过的维度不设为比赛项目。** 某指标不占优，就不要把叙事建立在该指标上；重选更能反映本文价值的任务定义、评价维度、应用场景或比较口径。
4. **优势必须被明确说出来。** 不指望审稿人自己从表格里发现贡献。
5. **控制比较范围。** 不追求「所有数据集、所有指标全面领先」，只提出证据能牢固支撑的主张。
6. **允许彻底重构故事。** 现有结果撑不起原始叙事时，重新定义问题、重排贡献、重选主结果。

### 语言规则（防自我削弱）
- 禁用自我削弱式表达：「遗憾的是」「仅」「仍明显落后」「效果有限」「存在严重不足」。
- **不说输。** 面对不占优的结果，按顺序判断：①该结果是否必须讨论；②能否从不同目标 / 约束 / 适用场景解释；③是否体现某种合理权衡；④能否收缩主张、避免正面对撞；⑤是否应调整故事主线。
- 某项结果不构成优势时，不必提炼成结论，更不应替读者把局部现象上升为对整体方法的否定。

### 结构规则
- **摘要和引言 = 发布会开场**，开头迅速建立四件事：①一个重要且尚未解决的问题；②现有方法的关键缺口；③本文独特的解决思路；④最有分量的结果和意义。不从实现细节或大量背景开始。
- **结论只强化记忆点。** 不在最后一段突然加入新的自我否定或扩大局限性。

### 交稿前自查（不给审稿人递刀子）
- 这句话是否无意中扩大了本文需要承担的责任？
- 是否提出了一个本来没人要求回答的问题？
- 是否把局部现象描述成了普遍缺陷？
- 是否使用了比证据更宽泛的负面判断？
- 有没有按「我们做了什么过程」在展开？
- 有没有把不领先的指标设成了主战场？
- 摘要前五句里，问题和贡献都出来了吗？
- 结论里有没有突然的自我否定？

> 一句话：**不主动制造审稿问题，不主动扩大攻击面，不主动替反方完成论证。**

## 二、改写尺度：只删防御动作，不删科学限制

这是最容易做错的地方。**方法学限制、样本量边界、口径限制、功效不足的声明——一律保留**；
要删的是：**重复**、**自证克制**（"我们不宣称…""须特别声明…"）、**预防假想误解**（替审稿人先攻击自己）。

| ❌ 反面写法（自证克制） | ✅ 正面写法 |
|---|---|
| 本研究存在多方面局限，尚不能证明该机制。 | 本稿可支持的边界：证据来自文献计量与既有队列，机制层级未被本稿数据直接检验。 |
| 我们不宣称该靶点已验证可成药（须特别声明）。 | 该靶点为机制候选；成药性验证不在本稿范围。 |
| 遗憾的是，中国团队影响力仍明显落后。 | （删判断句，改数据）中国团队篇均被引 7.46，低于海外 12.79。 |
| GSE263306 每群体 n=2 vs 2，效果有限，仅作参考。 | GSE263306 每群体 n=2 vs 2，结果按探索性趋势报告。 |

**注意边界**：**方法学限制列（如三态记账表）与边界声明不属"标签"，保留**。
要删的是**句内机挂标签**（"（本文数据支持的推断）"），不是方法学限制本身。

### 可复用的三步转换
1. **把限制改成正面范围陈述**：「本研究存在多方面局限」→「本研究的适用范围受以下边界限定」。
2. **把对冲词换成精确值**：「多数」→ 给数；「可能」→ 给区间或删掉。
3. **把否定式自证改成肯定式记账**：「正确表述为 X，不写作 Y」→「记作 X」。

## 三、docx 正文定点改写流程（落地到 Word）

需要在 **.docx 论文正文**上原地改写、保留格式时，走下面这套流程。

### 0. 备份（先做，别省）
```
cp -f "<正文>.docx" "<正文>.docx.bak.<YYYYMMDD>_<HHMM>_ADW前"
```

### 1. 提取正文为带行号的 raw.md
用 `python-docx` 遍历 `doc.paragraphs`，打印 `序号 + repr(文本)`，落到 `<短名>_raw.md`。
**这一步产出的序号即后续 E 表的键。**

### 2. 逐段判定
按第一节的检测清单过一遍，重点抓：
- 段首就摆限制 / 以「须声明」「须注意」「需要限定的是」起句
- 反复出现「不宣称」「不等价于」「不能写作 X」的否定式自证
- 高影响位置（摘要、小节首句、结论首句）堆 caveat
- 「不是 X 而是 Y」句式、冗余的「然而 / 尽管如此 / 虽然」

### 3. 写 E 表（**关键：行号口径**）
在改写脚本里定义 `E["<短名>"] = [(行号, 原串, 新串), ...]`：
- 行号用 **1-based**（就是第 1 步打印出来的序号）；
- 原串必须是**文档里的精确子串**（含全角标点、空格）；
- 新串填 `""` 表示整句 / 整段删除该子串；
- 同一段可有多条，按 order 依次命中。

### 4. 跑改写
引擎逻辑：
```python
paras = doc.paragraphs
for idx0, old, new in E[key]:
    p = paras[idx0 - 1]              # ← 1-based → 0-based，漏了这一步会全部 NOT_FOUND
    txt = "".join(r.text for r in p.runs)
    if old not in txt:
        print("NOT_FOUND", idx0, old[:30]); continue
    txt = txt.replace(old, new, 1)
    p.runs[0].text = txt             # 只写 runs[0]，其余 runs 清空 ⇒ 段落格式保留
    for r in p.runs[1:]:
        r.text = ""
```
跑完打印 `applied / NOT_FOUND` 计数；**有 NOT_FOUND 就回滚 docx 重来，别带病保存**。

### 5. 生成修改清单
配一张「段落号 → (命中规则, 说明)」的字典，产出《防御性写作修改清单_<日期>.md》：改前 / 改后对照 + 依据。

### 6. 复核
- 段数不变（`len(doc.paragraphs)` 与改前一致）；
- 重开 docx 抽查 3–5 处；
- 清单里每一处都能在 diff 里找到对应。

### 踩过的坑

| 坑 | 现象 | 处置 |
|---|---|---|
| **行号差一位** | 首跑 `applied: 0`，全 NOT_FOUND | `Read`/打印是 **1-based**，`paragraphs` 是 **0-based** → `idx = 行号 - 1` |
| **MSYS 路径** | `Package not found` | 本机 python 是 Windows 原生，**不认 `/d/...`**，必须用 `r"D:\..."` |
| **跨行段落** | 某处替换落到相邻段 | 在 raw.md 里定位段落边界，必要时用 `paras[i]` 单独补刀 |
| **直接改 run** | 字体 / 字号丢失 | 只改 `runs[0].text`，其余 runs 置空 |
| **多备份** | 目录里两份同名 bak | 只留一份，另一份删掉归一 |

> 注：本技能的检测脚本 `utils.py` 已支持**直接读 .docx**（zipfile 直读），
> 所以你可以先对 `.docx` 跑 `detox_pipeline.py` 定位高风险段，再用本节的定点流程改写。

## 四、与降 AI 循环的接口

1. `detox_pipeline.py <稿.docx> --json` → 拿到高风险段的行号与指令。
2. 按本节 §三 的定点改写流程，对**这些段**做反防御 + 去模板改写。
3. 复检：`detox_pipeline.py <新版.docx>`，确认 AIGC 疑似率下降且段数不变。
4. 过一遍 `05_reviewer_simulation.md`，确认改写没有把哪句从"防御腔"改成了"新攻击面"。
